# لوحة نسيج الإدارية — Super Admin Dashboard

لوحة **داخلية للمطور** لإدارة اشتراكات العملاء وتفعيل نسخهم. التطبيق مستقل تمامًا عن تطبيق العميل (POS) وعن أداة التفعيل: لا يدخل في مثبت العميل، ولا يُسلَّم لأي عميل.

## ما الذي تفعله اللوحة

- **الخزنة (Vault):** تحتفظ بمفتاح توقيع Ed25519 في ملف `vault.bin` داخل مجلد بيانات التطبيق. البذرة مشفّرة بـAES-256-GCM، ومفتاح البيانات ملفوف مرتين: مرة بمفتاح مشتق من كلمة مرور المشغّل عبر Argon2id، ومرة بـ**Windows DPAPI** في نطاق حساب المشغّل. المفتاح موجود في الذاكرة فقط أثناء فتح الخزنة. يمكن استيراد مفتاح توقيع موجود بدل توليد مفتاح جديد.
- **الاشتراكات:** كل رخصة صدرت من هذا الجهاز مسجّلة: العميل، الجهاز، الخطة، تاريخ الانتهاء، الميزات والحدود، وحالة السداد.
- **الإصدار:** تستورد ملف طلب التفعيل (`.req`) الذي أرسله العميل، وتصدر له رخصة موقّعة بتجربة 7 أيام أو اشتراك 12 شهرًا، وتكتب ملف `.lic` جاهزًا للتسليم.

## الفصل بين المفتاح والتطبيق

- تطبيق العميل (POS) يحتوي على **المفتاح العام فقط** (`NASEEJ_LICENSE_PUBLIC_KEY_HEX` وقت البناء) ولا يحتوي على أي مفتاح توقيع ولا بذرة.
- مفتاح التوقيع لا يغادر جهاز المطور: لا يوجد في المستودع، ولا في `dist`، ولا في ملفات البناء.
- كلمة مرور الخزنة لا تُحفظ في أي مكان؛ نسيانها يعني فقدان القدرة على توقيع رخص جديدة على هذا الجهاز (احتفظ بنسخة احتياطية مشفّرة منفصلة بإجراءكم الداخلي).
- **الخزنة مربوطة بحساب Windows.** نسخ `vault.bin` إلى جهاز آخر أو إلى حساب Windows آخر لا يفتح الخزنة: DPAPI لا يفكّ الغلاف إلا داخل حساب المشغّل. ولهذا التطبيق يعمل على Windows فقط، ويقول بوضوح `VAULT_DPAPI_UNAVAILABLE` على أي نظام آخر بدل أن يفتح خزنة بلا حماية.

## حدود معروفة

- **الإصدار أوفلاين بالكامل.** لا يوجد خادم ولا اشتراك سحابي.
- **الإلغاء لا يصل إلى جهاز غير متصل.** إلغاء الاشتراك يُسجَّل في سجل هذا الجهاز ويمنع التجديد أو إعادة الإصدار لنفس العميل، لكنه لا يُبطل رخصة سُلِّمت بالفعل للعميل. أبطل الرخصة من جهة العميل أو أوقف التفعيل عند التجديد.
- **خزنة على نظام الملفات.** الحماية هنا بقدر قوة كلمة المرور وحساب Windows وجهاز المشغّل، ومن يقرأ ذاكرة العملية أثناء فتح الخزنة يقرأ المفتاح. في بيئة إنتاج، استبدل الخزنة بـ HSM أو Windows CNG مع صلاحيات مُدقَّقة وسجل تدقيق.

## التشغيل

```bash
cd apps/super-admin
npm install
npm run tauri dev     # نسخة التطوير
npm run tauri build   # حزمة NSIS (لا تُوزَّع على العملاء)
```

أو من سطر الأوامر المرجعي (نفس السجل ونفس الصيغة):

```bash
cd tools/license-issuer
cargo run --release -- issue --request ./request.req --customer-id CUST-001 --plan trial-7d \
  --private-key-file E:\issuer-secrets\ed25519-seed.bin \
  --features pos.sell,inventory.manage,returns.exchange,reports.basic,backup.restore \
  --max-users 3 --max-branches 1
cargo run --release -- list
```

كلاهما يقرأ ويكتب سجل الاشتراكات نفسه، فترى في سطر الأوامر ما صدر من اللوحة والعكس.
