# استراتيجية استيراد البيانات من النظام القديم

## الصيغ

- CSV بـ UTF-8 (ويُقبل BOM)؛ يختار المستخدم delimiter والـ decimal separator إن لزم.
- Excel `.xlsx` عبر parser محلي؛ لا تُرفع الملفات لأي خدمة خارجية.
- لا ندعم `.xls` الثنائي القديم في المرحلة الأولى إلا بتحويله محليًا إلى `.xlsx`/CSV بعد فحصه.

## خطوات الاستيراد

1. **نسخة احتياطية أولًا**: إنشاء `.bkz` قبل بدء الدفعة.
2. **تحديد النوع**: أصناف، متغيرات/SKU، مخزون افتتاحي، عملاء، موردون، أوامر شراء. اختيار الفرع الواحد الحالي.
3. **معاينة الأعمدة**: ربط أعمدة الملف بـ حقول النظام، مثال: `اسم الصنف` → `product.name_ar`، `المقاس` → `size_code`, `اللون` → `color`, `الباركود` → `barcode`, `الرصيد` → `opening_qty`.
4. **معاينة صفوف حقيقية**: أول/آخر صفوف + عينة عشوائية، تطبيع العربية (أ/إ/آ، التشكيل، التطويل) مع الاحتفاظ بالقيمة الأصلية.
5. **تحقق دون كتابة**: نوع البيانات، الأسعار بوحدة قرش، الحقول المطلوبة، SKU/باركود فريد، تطابق المقاس واللون، فئة موجودة، كمية صحيحة، عدم وجود تكرار.
6. **تقرير الأخطاء**: رقم الشيت/الصف/العمود، القيمة بعد الإخفاء إن كانت شخصية، رمز الخطأ، اقتراح التصحيح. يتيح تنزيل تقرير CSV منفصل؛ لا يضع بيانات العملاء كاملة في log.
7. **مراجعة الفروقات**: عرض عدد الأصناف والمتغيرات، إجمالي الأرصدة/القيمة التقديرية، الباركودات المتكررة، المنتجات بلا صورة، وأرصدة الصنف الإجمالية التي لا يمكن توزيعها على المقاسات والألوان.
8. **اعتماد المدير**: لا يكتب النظام حتى يضغط مدير/مالك اعتماد. كل batch لها `import_batch_id` وchecksum للمصدر وفاعل ووقت.
9. **تنفيذ transactionally**: إنشاء المنتج/المتغيرات ثم حركات `OPENING_BALANCE` لكل SKU. لا تُكتب قيمة المخزون مباشرة؛ ledger هو المصدر.
10. **نتيجة نهائية**: imported / skipped / errors، تنزيل تقرير، وحفظ batch status. يمكن التراجع فقط بإدخال حركات عكسية مرتبطة بالدفعة مع سبب، لا بحذف السجلات.

## قواعد مطابقة SKU والباركود

- المفتاح المفضل للمتغير: SKU ثابت يخص المقاس واللون.
- الباركودات الحالية تُحفظ كما هي إذا كانت فريدة وصحيحة. المتغير بلا باركود يحصل على Code 128 داخلي فريد.
- لا يُسمح لباركود واحد أن يشير إلى أكثر من تركيبة منتج/مقاس/لون داخل الفرع.
- لو النظام القديم لا يميز المقاس واللون، لا يفترض البرنامج التوزيع آليًا؛ يضع الرصيد في قائمة «بحاجة لتوزيع يدوي» ويمنع اعتماد افتتاح المخزون حتى يحسمها المالك.
- لا يتم استيراد بيانات بطاقة بنكية أو كلمات مرور أو معلومات غير لازمة.

## ضمانات

- ملف Excel لا ينفّذ macros ولا صيغًا؛ تُقرأ القيم فقط، وتُرفض الروابط الخارجية.
- تحديد حد حجم الملف والصفوف، إلغاء الاستيراد الطويل، وحفظ preview مؤقت في الذاكرة/DB المشفرة.
- يظل المصدر الأصلي لدى المستخدم؛ لا يحذف البرنامج الملف.
- اختبار parsing لملفات عربية، Excel dates، أرقام EGP، باركودات تبدأ بصفر، أسطر فارغة، وصيغ مرفوضة.
