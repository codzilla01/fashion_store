## 1. بوابات ما قبل البيع (Pre-sale gates)

These must all pass before a paying customer is onboarded.

### 1.1 البوابة التقنية

- [ ] **مفتاح توقيع إنتاجي**: إنشاء seed عشوائي 32-byte على جهاز إصدار معزول.
      لا يُوضع في Git ولا في ZIP العميل.
- [ ] **حقن المفتاح العام في البناء**:
      `NASEEJ_LICENSE_PUBLIC_KEY_HEX=<64 hex chars>` عند بناء الإصدار.
      بدونه يرفض التطبيق كل الرخص (`PUBLIC_KEY_NOT_CONFIGURED`).
- [ ] **توقيع الـ EXE والمثبت** بشهادة Code Signing من CA موثوق.
- [ ] **اختبار بناء نظيف**: من `git clone` نظيف → `npm ci` → `tauri build` ينجح.
- [ ] **SBOM**: توليد `bom.json` / `bom.xml` لنسخة الإصدار وإرفاقه.

### 1.2 البوابة الأمنية

- [ ] **SQLCipher**: `PRAGMA cipher_version` غير فارغ على جهاز التثبيت.
- [ ] **قاعدة بدون مفتاح**: فتح `store.db` بمفتاح خاطئ **يفشل**.
- [ ] **DPAPI**: استرجاع `db-key.dpapi` على نفس حساب Windows **ينجح**،
      وعلى حساب/جهاز آخر **يفشل**.
- [ ] **النسخ الاحتياطي**: إنشاء `.bkz` → استعادة على جهاز آخر → البيانات سليمة.
- [ ] **كلمة مرور خاطئة** للاستعادة **مرفوضة** بلا تعديل البيانات الحية.
- [ ] **سلوك عند نفاد القرص / انقطاع الكهرباء** أثناء إنشاء نسخة.
- [ ] **ACLs**: `%LOCALAPPDATA%\NaseejPOS` غير مقروء لحسابات أخرى.
- [ ] **خزنة التوقيع**: نسخ `vault.bin` إلى حساب Windows آخر أو جهاز آخر **لا يفتح
      الخزنة**، وفتح الخزنة على جهاز المطور بـWindows Hello أو بكلمة المرور يعمل.
      يجب أن يُجرى هذا على جهاز الم-developer الحقيقي، لأن DPAPI لا يعمل على
      جهاز افتراضي مشترك.
- [ ] **لا أسرار في السجلات**: لا رقم هاتف أو اسم عميل في ملفات السجل.

### 1.3 البوابة الوظيفية (مطلوبة من العميل)

- [ ] **الضريبة**: النسبة مثبّتة على 14% والأسعار المعروضة **غير شاملة** لها.
      يبقى اعتماد **آلية التقريب** مع محاسب المتجر، وللمالك تغيير النسبة أو طريقة
      العرض من لوحة التحكم، ويُسجَّل التغيير في `audit_log`.
- [ ] **سياسة المرتجعات**: القيمة الافتراضية 14 يومًا مضبوطة مسبقًا، والمالك هو من
      يضبطها من لوحة التحكم (المدة، قبول الأصناف المخفّضة، الحالات المسموح
      بإرجاعها للمخزون). يبقى اعتماد: هل يلزم الإيصال، ورد المبلغ نقدًا أم على
      الوسيلة أم رصيدًا.
- [ ] **الأجهزة**: موديل الماسح، عرض طابعة الفاتورة (58 أو 80mm)،
      طابعة الملصقات ومقاس الورق.
- [ ] **الترخيص**: هل التجربة التلقائية 7 أيام كافية؟ هل مهلة السماح 14 يومًا
      مناسبة؟ سياسة تكرار التجربة.
- [ ] **النسخ**: وجهة النسخ (USB؟)، من المسؤول عن كلمة مرور الاستعادة،
      وتكرار اختبار الاستعادة شهريًا.

### 1.4 البوابة التشغيلية

- [ ] تثبيت على جهاز المتجر مع **Windows 10/11** و**WebView2** محدث.
- [ ] إنشاء حساب المالك (لا توجد كلمة مرور افتراضية).
- [ ] مراجعة الضريبة (14%، غير شاملة) من لوحة المالك قبل أول بيع.
- [ ] تسجيل بصمة جهاز المالك من لوحة التحكم (Windows Hello) بعد أول دخول،
      حتى يفتح اللوحة لاحقًا بدون كلمة مرور.
- [ ] إدخال الفئات/المقاسات/الألوان والمنتجات الافتتاحية.
- [ ] إدخال أرصدة الافتتاح كحركات `OPENING_BALANCE` (لا كتابة مباشرة للرصيد).
- [ ] **نسخة احتياطية أولى** قبل إدخال أي بيانات فعلية.
- [ ] اختبار بيع/مرتجع/تقرير على بيانات تجريبية.
- [ ] تدريب الكاشير على: المسح، الدفع المقسّم، إعادة الطباعة، الإغلاق اليومي.

## 2. بناء الإصدار

### 2.1 المتغيرات المطلوبة

| المتغير | مطلوب | الوصف |
|---|---|---|
| `NASEEJ_LICENSE_PUBLIC_KEY_HEX` | ✅ للإصدار | المفتاح العام Ed25519 (64 hex) |
| `NASEEJ_LICENSE_GRACE_DAYS` | اختياري | أيام مهلة السماح (افتراضي 14) |

> `NASEEJ_LICENSE_PUBLIC_KEY_HEX` يُقرأ وقت **البناء** (`option_env!`).
> تغييره بعد البناء يتطلب إعادة بناء التطبيق كاملًا.

### 2.2 بناء المثبت

```powershell
git clone <repo> && cd fashion_store
cd apps/pos-desktop
npm ci
$env:NASEEJ_LICENSE_PUBLIC_KEY_HEX = "<64 hex chars>"
npm run tauri build -- --bundles nsis
```

الناتج: `src-tauri/target/release/bundle/nsis/*.exe`

### 2.3 البناء في CI

المستودع يحتوي على `.github/workflows/ci.yml` الذي:

1. يبني الواجهتين.
2. يشغّل اختبارات المخطط.
3. يفحص `fmt`/`clippy` ويشغّل اختبارات Rust على Linux وWindows.
4. **يشغّل اختبارات SQLCipher/DPAPI/النسخ على Windows حقيقي.**
5. يبني مثبت NSIS ويرفعه كartifact.

لإطلاق حقيقي، أضف سرًا في GitHub:

```
Settings → Secrets and variables → Actions → New repository secret
Name:  NASEEJ_LICENSE_PUBLIC_KEY_HEX
Value: <64 hex chars>
```

### 2.4 التحقق منIntegrity قبل التسليم

```powershell
Get-FileHash .\naseej-pos-0.1.0-setup.exe -Algorithm SHA256
```

احفظ البصمة، وأرفقها مع ملف التسليم، وقارنها عند الاستلام.

## 3. التفعيل للعميل (أوفلاين بالكامل)

العميل لا يحتاج إنترنت:

1. يفتح **Naseej Activation Tool** على جهاز المتجر.
2. يضغط **تصدير طلب التفعيل** → ينتج ملف `.req`.
3. ينقل الملف `.req` إلى مسؤول التفعيل (USB/بريد).
4. المسؤول يفتح **لوحة نسيج الإدارية** (`apps/super-admin`) على جهازه، أو
   يستخدم أداة سطر الأوامر، ويصدر الرخصة. بلوحة الإدارة:

   ```text
   الخزنة → إنشاء/فتح (كلمة مرور الخزنة) → الاشتراكات → استيراد ملف .req
   → إدخال معرّف العميل والخطة → إصدار الاشتراك → نسخ محتوى الرخصة
   ```

   وبأداة سطر الأوامر:

   ```powershell
   cd tools/license-issuer
   cargo run --release -- issue `
     --request .\request.req `
     --customer-id CUST-001 `
     --plan trial-7d `
     --private-key-file E:\issuer-secrets\ed25519-seed.bin `
     --features pos.sell,inventory.manage,returns.exchange,reports.basic,backup.restore `
     --max-users 3 `
     --max-branches 1
   ```

5. ينقل ملف `.lic` إلى جهاز العميل ويستورده من ActivationTool.
6. العميل يشغّل POS — الحالة `ACTIVE`.

للاشتراك السنوي استخدم `--plan annual-12m`.

> **بدون خطوة 4** يعمل العميل تلقائيًا في **نسخة تجريبية محلية 7 أيام**
> تبدأ من أول تشغيل للبرنامج. بعدها يدخل مهلة سماح 14 يومًا، ثم تتوقف
> 기능 البيع حتى صدور رخصة موقّعة.

## 4. نقل الجهاز أو استبدال القرص

1. العميل ينشئ `.req` جديدًا من الجهاز/القرص الجديد.
2. المسؤول يصدر `.lic` جديدة مرتبطة بالبصمة الجديدة.
3. العميل يستورد `.lic` على الجهاز الجديد.
4. **استعادة البيانات**: يُنقل ملف `.bkz` إلى الجهاز الجديد ويُستعاد بكلمة المرور.
   لا يُنسخ `db-key.dpapi` بين الأجهزة — يُنشأ مفتاح DB محلي جديد تلقائيًا.

## 5. النسخ الاحتياطي (سياسة مقترحة)

| النوع | التواتر | الاحتفاظ |
|---|---|---|
| يومية | كل ليلة بعد الإغلاق | 14 يومًا |
| أسبوعية | كل جمعة | 8 أسابيع |
| شهرية | أول كل شهر | 12 شهرًا |

- احتفظ **نسخة خارج الجهاز** (USB أو قرص خارجي).
- **اختبر استعادة حقيقية شهريًا** — وجود الملف ليس اختبارًا.
- لا تُسجَّل كلمة مرور النسخة أو مفتاحها في السجلات.

## 7. ما لا يدخل ملف التسليم

- ❌ `tools/license-issuer` (أداة إصدار الرخص)
- ❌ `apps/super-admin` (لوحة المطور)
- ❌ أي private key أو seed
- ❌ سجل الإصدار المحلي `NaseejLicenseIssuer`
- ❌ أي `.req`/`.lic` أو `.bkz` خاص بمحل آخر
