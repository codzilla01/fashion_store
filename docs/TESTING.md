## 1. ما يُقاس تلقائيًا في CI

كل ما يلي يعمل في `.github/workflows/ci.yml` على كل push:

| البوابة | الأمر | نتيجة |
|---|---|---|
| بناء واجهة POS | `npm run build` (tsc + vite) | ✅ |
| بناء واجهة أداة التفعيل | `npm run build` | ✅ |
| اختبارات المخطط | `python -m unittest discover -s tests -v` | ✅ 10 اختبارات |
| تنسيق Rust | `cargo fmt --check` (4 crates) | ✅ |
| اختبارات `license-format` | `cargo test --all-features` | ✅ |
| اختبارات `license-issuer` | `cargo test --all-features` | ✅ |
| فحص POS + أداة التفعيل | `cargo check --all-targets` | ✅ |
| Clippy | `cargo clippy -- -D warnings` | ✅ |
| **SQLCipher / DPAPI / النسخ على Windows** | `cargo test --test windows_security` | ✅ على `windows-latest` |
| **مثبت NSIS** | `npm run tauri build -- --bundles nsis` | ✅ artifact |

### لماذا `cargo fmt` لا يُفشل البناء

ال的风格 مطبّق تلقائيًا: job باسم `Apply rustfmt` يشغّل `cargo fmt` على كل
crate ثم يدفع النتيجة. هذا يمنع أن يتعطل البناء بسبب مسافة بادئة، ويبقي
الفرق على الشيفرة فقط.

### تشخيص الأعطال

سجلات الـCI تُحمَّل من blob محجوب، لذلك **فشل البناء ينشر تشخيصه كتعليق
على الـcommit** عبر `POST /repos/{owner}/{repo}/commits/{sha}/comments`:

```bash
gh api repos/codzilla01/fashion_store/commits/<sha>/comments --jq '.[].body'
```

## 2. اختبارات المخطط (Python + SQLite عادي)

`tests/test_schema_smoke.py` — **10 اختبارات ناجحة**:

1. رصيد المتغير على مستوى SKU مع تفعيله من دفتر المخزون.
2. تفرد SKU والباركود داخل الفرع.
3. دفتر المخزون append-only (لا تعديل ولا حذف).
4. rollback لا يترك فاتورة جزئية.
5. المدير والمالك يملكان صلاحية التكلفة، والصندوق لا يملكها.
6. إدارة الفروع للمالك فقط، والمهاجرة قابلة للتكرار.
7. أعمدة hash الطلب موجودة لـ idempotency.
8. الاستبدال يربط المرتجع بالفاتورة الجديدة مع صافي المخزون.
9. **حالة التجربة المحلية**: صف واحد فقط، ولا تحديث ولا حذف.
10. **بصمة الجهاز مسجَّلة** في حالة التجربة.

> ⚠️ هذه الاختبارات تستخدم SQLite النظام، **ولا تختبر SQLCipher أو DPAPI**.

## 3. اختبارات Windows الحقيقية (SQLCipher / DPAPI / النسخ)

`apps/pos-desktop/src-tauri/tests/windows_security.rs` — تعمل على `windows-latest`:

| الاختبار | ما يثبته |
|---|---|
| `sqlcipher_is_active_and_rejects_a_wrong_key` | `PRAGMA cipher_version` غير فارغ، والفتح بمفتاح خاطئ **يفشل** |
| `dpapi_protects_the_database_key_per_windows_user` | المفتاح محمي بـDPAPI ولا يُقرأ كمادة صريحة |
| `personal_fields_are_encrypted_at_rest` | حقول العملاء الشخصية (الاسم/الهاتف/البريد) مشفّرة في قاعدة البيانات |
| `backup_round_trip_restores_the_database` | إنشاء `.bkz` واستعادته يعيد البيانات سليمة |
| `backup_rejects_a_wrong_password` | كلمة مرور خاطئة **مرفوضة** ولا تُعدّل البيانات الحية |
| `migrations_are_reopenable` | فتح/إغلاق/إعادة فتح القاعدة يعمل، والمهاجرات قابلة للتكرار |

> هذه هي **البوابة الوحيدة** التي تُثبت أن SQLCipher وDPAPI يعملان فعليًا.
> لا يمكن استنساخها خارج Windows.

## 7. ما لم يُثبت بعد — لا تعتبر المنتج جاهزًا للإنتاج

- ⛔ **مفتاح توقيع إنتاجي غير موجود.** كل بناء من CI نسخة تطوير
      (`is_production_key_configured() == false`)، والتطبيق يرفض أي رخصة
      موقّعة ويعرض تحذيرًا أحمر داخل الواجهة.
- ⛔ **لا يوجد EXE موقّع.** المثبت يُبنى لكن غير موقّع بـCode Signing.
- ⛔ **لا يوجد اختبار على جهاز Windows فعلي** (WebView2، طابعة، ماسح).
- ⛔ **الطباعة على طابعة حقيقية لم تُختبر**؛ المنطق مُختبر والـspooler مُترجم فقط.
- ⛔ **الاستيراد CSV/XLSX غير منفّذ** (موثق في `docs/IMPORTS.md` فقط).
- ⛔ **الولاء غير منفّذ** (الجدول موجود، التدفق ناقص).
- ⛔ **تجربة التراجع عن الساعة غير كاملة**: يُرصد الرجوع > 5 دقائق،
      لكن **تقديم** الساعة غير مرصود.
- ⛔ **حذف قاعدة البيانات = إعادة التجربة** (لا يوجد ربط بمفتاح خارجي).
- ⛔ **بصمة الجهاز (SMBIOS UUID) تتغير** عند تبديل اللوحة الأم أو في VM.
- ⛔ **لا توجد اختبارات قبول** على نسخة Windows نظيفة، ولا اختبار انقطاع
      كهرباء أثناء إنشاء نسخة.
- ⛔ **سياسة المرتجعات، شمول الضريبة والتقريب، التسعير، سياسة النقل**
      غير معتمدة من المالك (انظر `docs/LICENSING.md`).
