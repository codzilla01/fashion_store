## اختبارات القبول الإلزامية

- [ ] تثبيت على Windows نظيف + WebView2 محدث، وتشغيل التطبيق دون أخطاء.
- [ ] إنشاء حساب المالك بأول دخول، وتسجيل بصمة Windows Hello/جهاز آخر.
- [ ] الضريبة اختيارية: التأكد أن أول تشغيل لا يطلب ضريبة وأن الفاتورة تُحفظ بدونها.
- [ ] تشغيل الضريبة من لوحة المالك عند 14% غير شاملة، والتأكد من التقريب لأقرب ١ ج.م، ثم إيقافها والعودة للبيع بدون ضريبة.
- [ ] فاتورة ببندين متساويين (مثال 88.60 ج.م × 2) والضريبة مفعّلة: الإجمالي المطبوع يساوي الإجمالي المُحصَّل بالضبط.
- [ ] دفع نقدي أكبر من الإجمالي (ورقة 200 لفاتورة 18.15): ظهور الباقي، وحفظ الفاتورة بإجماليها لا بالمبلغ المدفوع.

- [ ] بيع تجريبي كامل: مسح باركود → دفع مقسّم → طباعة فاتورة → إعادة طباعة.
- [ ] مرتجع تجريبي: رد رصيد للعميل، وتأكيد عدم زيادة رصيد قطعة غير صالحة للإرجاع للمخزون.
- [ ] استبدال تجريبي بفاتورة جديدة وتسجيل فرق السعر ذريًا.
- [ ] تقرير يومي بالضريبة والمبيعات مطابق للفواتير اليدوية (مع الضريبة مفعّلة وموقوفة).
- [ ] استيراد ملف CSV وملف XLSX تجريبيين: ظهور المعاينة والأخطاء، ولا كتابة قبل الاعتماد، ثم اعتماد الدفعة وظهور الأصناف والمخزون.
- [ ] الولاء: تفعيله، احتساب النقاط على بيع تجريبي، ثم إرجاع كامل للفاتورة والتأكد من عكس النقاط.
- [ ] رصيد العميل: إرجاع مبلغ رصيدًا، ثم استخدامه كطريقة دفع في فاتورة لاحقة.
- [ ] نسخة `.bkz` على USB، ثم استعادة على جهاز ثانٍ وفتح البيانات سليمة.
- [ ] رفض كلمة مرور استعادة خاطئة دون تعديل قاعدة البيانات الحية.
- [ ] اختبار استعادة أسبوعي موثّق (الأسبوع الأول قبل الإصدار).
- [ ] انقطاع كهرباء أثناء البيع: لا فاتورة بلا حركة مخزون ولا العكس.
- [ ] انقطاع كهرباء أثناء إنشاء `.bkz`: لا ملف تالف يُقبل عند الاستعادة.
- [ ] فتح `store.db` بمفتاح خاطئ يفشل، واسترجاع مفتاح DPAPI على حساب آخر يفشل.
- [ ] لا تظهر بيانات عملاء أو أرقام هواتف في سجلات التطبيق.
- [ ] تدريب الكاشير على المسح والدفع المقسّم وإعادة الطباعة والإغلاق اليومي.
