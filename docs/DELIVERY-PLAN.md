# خطة التنفيذ المرحلية والقرارات المطلوبة

> **ملاحظة حالة (2026-10-11):** الخطة أدناه تصف معايير القبول النهائية، وليست ادعاءً بأن كل مرحلة مُعتمدة للإنتاج. يوجد في المصدر الآن تنفيذ محلي لجزء كبير من التدفقات: POS/الكتالوج/متغيرات المخزون/المبيعات، العملاء والموردون والمشتريات والتقارير، RBAC وإدارة الفروع، النسخ الاحتياطي المشفر، المرتجعات والاستبدال، وتفعيل أوفلاين عبر تطبيق مستقل. ما زالت استيرادات CSV/XLSX والولاء وبعض تفاصيل الطباعة/الأجهزة والاختبارات التشغيلية الكاملة غير منجزة/غير معتمدة. لا تُعتبر أي مرحلة إصدارًا إنتاجيًا حتى تمر اختبارات Windows وSQLCipher وDPAPI والاستعادة والقبول؛ راجع [TESTING.md](TESTING.md) للحالة المقاسة.

## المراحل

### المرحلة 0 — تأسيس تقني/قبول (1–2 أسبوع تقديري)
- تثبيت Tauri/React/TypeScript وRust toolchain على Windows 10/11 نظيف.
- تهيئة SQLCipher، DPAPI، ملف DB في LocalAppData، ومهاجرات versioned.
- تعيين RBAC، bootstrap owner، lock screen، لغتين RTL/LTR.
- إقرار خرائط الضرائب، المقاسات، الباركود والأجهزة قبل تسجيل بيانات فعلية.

**خروج المرحلة:** فحص `cipher_version` يؤكد SQLCipher، DB لا تفتح بلا مفتاح، وتعمل أول migration/reopen على Windows.

### المرحلة 1 — MVP: البيع/الكتالوج/المخزون/الفواتير
- الفئات/الماركات/الموسم/المنتج والوصف والصورة المحلية.
- مقاسات وألوان متعددة لكل SKU مع SKU/باركود مستقل ومخزون لكل متغير.
- استلام افتتاحي/تسوية أولية، بحث سريع بالباركود، سلة، خصم، tax engine قابل للتهيئة، وسائل دفع متعددة.
- إنشاء فاتورة transactionally، حركة مخزون، printable receipt، إعادة طباعة، منع البيع الناقص افتراضيًا.
- شاشة المنتجات/الرصيد/إعادة الطلب مع صلاحيات cashier/manager/owner.

**اختبارات الخروج:** بيع صحيح؛ دفع ناقص/زائد مرفوض؛ كمية SKU منفصلة؛ ضغط مرتين idempotent؛ كسر DB/انقطاع قبل commit لا يترك فاتورة بلا حركة أو العكس.

### المرحلة 2 — العملاء والولاء
- عميل اختياري، رقم هاتف وملاحظات مشفرة، HMAC lookup للبحث المطابق، سجل موافقة.
- نقاط دفترية لا تتغير مباشرة؛ كسب/استبدال/تصحيح مع سبب، وسياسة انتهاء.

### المرحلة 3 — الموردون والمشتريات والاستيراد
- الموردون، Purchase Orders، استلام جزئي/كامل، فاتورة مورد وتكلفة شراء، حركة مخزون بالاستلام فقط.
- معالج استيراد CSV/XLSX: تحميل، مطابقة الأعمدة، معاينة، validation لكل صف، تقرير أخطاء، تنفيذ على دفعات بعد موافقة المدير.

### المرحلة 4 — المرتجعات والاستبدال
- اختيار فاتورة أصلية وبنود/كميات مرجعة، سبب وحالة القطعة.
- سياسة مدة/استثناءات؛ المبيعات المرجعة لا تدخل المخزون الصالح إلا عند `RESTOCKABLE`.
- رد مبلغ على وسيلة أصلية/نقدًا/رصيد، واستبدال كفاتورة جديدة تسوي فرق السعر في transaction واحدة مع سجل تدقيق.

### المرحلة 5 — التقارير والموظفون والعمولات
- مبيعات يومية/شهرية حسب SKU/family/category/size/color، مرتجعات، هامش، قيمة مخزون، slow movers، reorder.
- تقارير تكاليف/أرباح/عمولات للمدير والمالك فقط. ورديات اختيارية وcash drawer reconciliation.

### المرحلة 6 — النسخ/التفعيل/الطباعة والإصدار
- `.bkz` مجدول/يدوي، تدوير، وجهة USB، استعادة إلى ملف staged والتحقق ثم swap.
- ActivationTool مستقل بـ `.req/.lic`, verification public-only, clock anomaly handling، أداة إصدار داخلية وحفظ المفتاح في HSM/جهاز معزول.
- طباعة 58/80mm وملصقات على الموديلات الفعلية، شاشة عميل اختيارية، توقيع وتثبيت Windows، اختبار قبول/تدريب.

## استراتيجية الاختبار

### اختبارات منطقية/تكامل

- البيع: stock 1 وطلب qty 2، خصم مع/بدون صلاحية، الضريبة شاملة/غير شاملة، التقريب، وسائل دفع split، invoice duplicate/idempotency.
- تخزين: `BEGIN IMMEDIATE`; foreign key; trigger append-only; سحب الكهرباء/قتل العملية حول commit ثم reopen؛ `integrity_check`.
- إرجاع: فاتورة أصلية مطابقة، تجاوز الكمية المباعة/المتبقية مرفوض، قطعة تالفة لا تزيد stock sellable، رد نقدي وفرق استبدال.
- الجرد: فرق موجب/سالب وسبب/اعتماد؛ حركتان عكسيتان؛ لا بيع كمية غير متاحة دون toggle وpermission.
- backup: إنشاء، tamper bit، password خطأ، ملف مبتور، media ناقصة، schema أقدم/أحدث؛ لا يُمس DB الحي عند أي فشل؛ restore إلى DB فارغ وفحص العلاقات.
- الترخيص: توقيع صحيح/خاطئ، جهاز آخر، منتج آخر، انتهاء/بدء، feature limits، `.req` invalid، rollback clock عارض، نسخة الرخصة.
- الطباعة: printer offline/spooler error بعد commit، إعادة محاولة دون فاتورة/حركة جديدة.
- الصلاحيات: cashier لا يستطيع جلب cost/profit/report عبر command حتى لو استدعى IPC يدويًا.

### اختبارات تشغيل Windows

- Windows 10/11، WebView2، User Account Control، تحديث البرنامج، إعادة تشغيل أثناء backup، قرص ممتلئ، USB إزالة أثناء الكتابة، طابعة offline، قارئ USB يرسل input بسرعة.
- اختبار DB schema upgrade على نسخة فعلية ثم rollback/restore.
- مراجعة أمنية للـ IPC، ACL، سجل التدقيق، الأسرار والـ installer.

المفصل في [IMPORTS.md](IMPORTS.md). يمنع ترحيل كمية رصيد كرقم إجمالي للصنف؛ يجب ربط كل رصيد بمتغير المقاس/اللون/الباركود أو يراجع يدويًا.

## قرارات يلزم اعتمادها قبل إنتاج

1. **الضريبة:** 14% بحسب الإجابة، لكن هل السعر المعروض شامل أم غير شامل؟ هل توجد فئات/إعفاءات أخرى؟ ما سياسة التقريب؟ يؤكدها محاسب المتجر.
2. **المرتجعات:** عدد الأيام، الإيصال، tag/حالة القطعة، السلع المخفضة، رد نقدي أم وسيلة أصلية أم رصيد، ومن يوافق على الحالات الاستثنائية.
3. **الأجهزة:** موديل الماسح (USB HID/serial)، طابعة الفاتورة 58 أو 80mm وموديل/ESC-POS/driver، طابعة الملصقات ومقاس الورق.
4. **المقاسات والألوان:** XS–XXL كخط بداية، هل يوجد أطفال/One size/مقاس رقمي؟ هل أسماء الألوان مطلوبة بالعربية والإنجليزية؟
5. **الترخيص:** مدة التجربة (7 أيام) والاشتراك (12 شهرًا تقويميًا) مثبتتان في مصدر issuer الحالي. يلزم اعتماد سياسة إعادة التجربة، التسعير/التحصيل، مهلة السماح وما يحدث بعد الانتهاء، قناة استقبال `.req`، SLA نقل الجهاز، وعدد الأجهزة/المستخدمين والفروع.
6. **النسخ:** وجهة USB الافتراضية، الاحتفاظ، مسؤول كلمة مرور الاستعادة، هل يلزم نقل النسخة إلى جهاز آخر.
7. **العمليات:** عدد الكاشيرين، طريقة فتح وردية/إغلاقها، سقف الخصم بلا موافقة، السماح بدين/بيع ناقص.
8. **بيانات النظام القديم:** نموذج CSV/XLSX لكل جدول وعينة منزوعة البيانات الحساسة.

## المخاطر/الافتراضات

- النظام على جهاز واحد/فرع واحد؛ لا توجد مزامنة أو تعدد أجهزة في الإصدار الأول.
- Tauri وSQLCipher ومكتبات التشفير تحتاج build واختبار فعلي على Windows؛ معاينة المتصفح ليست اختبارًا لتشفير DB.
- تغيير اللوحة الأم/TPM أو إعادة تثبيت Windows قد يستدعي إعادة تفعيل؛ لذلك دعم rehost مطلوب.
- لا يمكن جعل سجل محلي غير قابل للتعديل أمام Windows Administrator يسيطر على الجهاز؛ hash chain يكتشف العبث المعتاد لا يوقف خصمًا محليًا متمرسًا.
- فشل الطابعة لا يلغي البيع؛ يلزم تدريب الموظف على شاشة نجاح الحفظ وإعادة الطباعة.
- مدد التجربة والاشتراك في أداة الإصدار محددة إلى 7 أيام و12 شهرًا تقويميًا بناءً على توجيه المالك؛ مهلة السماح وسياسة التكرار غير محسومتين. نسبة الضريبة الافتراضية 14% تحتاج مراجعة محاسب، وليست استشارة قانونية/ضريبية.
