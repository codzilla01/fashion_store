# أداة إدارة الاشتراكات وإصدار التفعيل — داخلية فقط

`naseej-license-issuer` أداة مستقلة لإدارة سجل الإصدارات المحلي وإصدار ملفات `.lic` موقّعة لطلبات `.req`. لا تدخل في POS أو ActivationTool ولا تُضمّن في مثبت العميل. يحتوي العميل على مفتاح التحقق العام فقط؛ لا يوجد مفتاح توقيع إنتاجي داخل المستودع.

## الخطط المطبقة

- `trial-7d`: تجربة موقعة مرتبطة ببصمة الجهاز، صلاحيتها **7 أيام كاملة** من وقت الإصدار UTC.
- `annual-12m`: اشتراك مدته **12 شهرًا تقويميًا** من وقت الإصدار UTC.
- لا توجد مهلة سماح ضمن الرخصة بعد تاريخ الانتهاء. التجديد بإصدار ملف موقّع جديد لطلب جهاز جديد.
- يسجل البرنامج كل إصدار محليًا في ملفات JSON تحت مجلد registry، ويعرض `list` الحالة حسب وقت جهاز جهة الإصدار. إذا وُجدت تجربة سابقة للعميل أو الجهاز، يصدر تحذيرًا للمراجع؛ قرار إعادة التجربة لم يُقفل كسياسة تلقائية.
- لأن POS يعمل دون اتصال، **لا يمكن سحب رخصة وصلت بالفعل إلى جهاز غير متصل فورًا**؛ سجل الإدارة المحلي ليس قناة إلغاء عن بُعد.

## الاستخدام

يشغّل العميل `ActivationTool.exe` لإنشاء `.req` ونقله إلى مسؤول التفعيل. بعد مراجعة العميل، يصدر المسؤول تجربة أو اشتراكًا سنويًا:

```powershell
cd tools/license-issuer

cargo run --release -- issue `
  --request .\request.req `
  --customer-id CUST-001 `
  --plan trial-7d `
  --private-key-file E:\issuer-secrets\ed25519-seed.bin `
  --features pos.sell,inventory.manage,returns.exchange,reports.basic,backup.restore `
  --max-users 3 `
  --max-branches 1

cargo run --release -- list
```

للاشتراك السنوي استخدم `--plan annual-12m`. يمكن تمرير `--starts-at-utc <RFC3339>` لتحديد بداية مستقبلية؛ وإلا تبدأ المدة عند الإصدار. يجب اختيار حدود المستخدمين والفروع والميزات صراحةً لكل إصدار؛ لا تفرض الأداة أرقامًا تجارية افتراضية. ينتج ملف `.lic` بجانب الطلب، وتُحفظ بيانات الإصدار اللازمة في registry المستخدم. يمكن تحديد مساره بـ `--registry` أو `NASEEJ_ISSUER_REGISTRY`، ثم مراجعة السجل بـ `cargo run --release -- list`.

لاستخراج المفتاح العام المطابق من seed (لتهيئة متغير البناء العام فقط):

```powershell
cargo run --release -- public-key --private-key-file E:\issuer-secrets\ed25519-seed.bin
```

لا تُرسل seed إلى عميل POS أو ActivationTool. أمر `public-key` يطبع المفتاح العام وحده.

## حدود الأمان والجاهزية

- إدخال مفتاح خام من ملف 32-byte seed موجود **للتطوير/الاختبار الداخلي فقط**. لا تُشغّل إصدارًا تجاريًا بمفتاح ملف عادي؛ يلزم HSM أو Windows CNG، ACLs، صلاحيات موظفين ومراجعة مزدوجة، وسجل تدقيق محمي.
- لا تحفظ قاعدة registry سر التوقيع، لكنها تحتوي معرّف العميل وبصمة الجهاز ومسار ملف الرخصة؛ احمِ محطة الإصدار ونسخ registry وفق سياسة الشركة.
- التوقيع يحمي من تعديل الحقول؛ لا يحمي من العبث بساعة جهاز العميل وحده. الكود يكتشف رجوع الساعة محليًا بدرجة محدودة، ويلزم قبول واختبار استعادة/clock rollback على أجهزة Windows.
- التفعيل أوفلاين: الطلب والتوقيع والاستيراد محليًا، ولا يتطلب POS اتصالًا بالشبكة.
- إصدار مفتاح عام مطابق وحقنه في بناء POS وActivationTool، وتوقيع EXE/المثبت، واختبار Windows ما زالت خطوات إصدار مطلوبة. لا تضع أي private key في repository أو ZIP تسليم العميل.
