# نظام نقاط بيع وإدارة مخزون لمحل ملابس — POS

**المستهدف:** محل واحد حاليًا، مع `branch_id` في البيانات منذ البداية؛ Windows 10/11؛ واجهة عربية/إنجليزية؛ تشغيل محلي دون اتصال.

> **حالة المصدر في 2026-11-16:** يحتوي المستودع على مصدر تطبيق POS محلي بـ Tauri/React/Rust، ومشروع ActivationTool مستقل لطلب/استيراد الرخصة دون اتصال، وأداة إصدار/إدارة اشتراكات داخلية منفصلة عن العميل.
>
> **ما became مُقاسًا على Windows حقيقي:** SQLCipher مفعّل (والفتح بمفتاح خاطئ يفشل)، ومفتاح قاعدة البيانات محمي بـDPAPI، والحقول الشخصية مشفّرة، والنسخ `.bkz` المشفّر يُنشأ ويُستعاد (وكلمة المرور الخاطئة مرفوضة)، والمهاجرات قابلة لإعادة الفتح. كل ذلك داخل `cargo test --test windows_security` على `windows-latest`.
>
> **ما أُضيف حديثًا:** تجربة محلية تلقائية 7 أيام مربوطة ببصمة الجهاز (مسجَّلة في `local_trial_state` بسجل append-only)، مهلة سماح 14 يومًا بعد انتهاء الترخيص، **طباعة الفواتير** (نص 58/80mm + HTML + إرسال مباشر إلى طابعة Windows عبر `winspool`)، حارس يمنع شحن بناء بلا مفتاح ترخيص إنتاجي، ودليل تسليم/تشغيل/ترخيص تجاري.
>
> **ما زال ناقصًا (بوابات حقيقية لا يمكن تجاوزها):** لا يوجد مفتاح توقيع إنتاجي، ولا مثبت موقّع بـCode Signing، ولا اختبار على طابعة/ماسح فعليين، ولا استيراد CSV/XLSX، ولا ولاء. سياسات المرتجعات والضريبة والتقريب والتسعير لم تُعتمد بعد. **لا تُدخل بيانات متجر حقيقية قبل اجتياز `docs/RELEASE-CHECKLIST.md`.**

## ما تم تثبيته من إجاباتك

- المقاسات: جداول دولية (مثل XS–XXL)، مع قابلية إنشاء مقاسات أخرى لكل فئة.
- الأجهزة: إعداد متعدد متوقع، يشمل ماسح باركود وطابعة فواتير وطابعة ملصقات؛ الموديلات وعرض الفاتورة لم تُحدّد.
- سياسة المرتجعات: غير محسومة؛ ستبقى إعدادًا مطلوبًا من المالك قبل أول مرتجع.
- العملة والضريبة: EGP و14% كإعداد ابتدائي **بانتظار تحديد شمول الأسعار والتحقق المحاسبي/القانوني**.
- الباركود: استيراد الموجود وتوليد Code 128 داخليًا للمتغيرات التي لا تحمل باركود.
- الترخيص: تفعيل أوفلاين بملفي `.req` و`.lic`؛ أداة الإصدار تدعم تجربة موقعة 7 أيام واشتراكًا لمدة 12 شهرًا تقويميًا. مهلة السماح، سياسة تكرار التجربة، التسعير والتحصيل لم تُحسم.

## التقنية المقترحة

- Tauri 2.x + React/TypeScript وWebView2 على Windows.
- Rust backend؛ لا يُسمح للواجهة بإرسال SQL عام.
- SQLCipher مضمّن في بناء Windows، وقاعدة `rusqlite` لا تُفتح إلا بعد تطبيق المفتاح. طبقة الوصول تكون مستودعات typed/repository ومهاجرات SQL، بدل إضافة ORM لا يضمن SQLCipher فعليًا.
- تخزين المفتاح المحلي عبر Windows DPAPI، مع سر عشوائي مستقل عن بصمة الجهاز. لا تُشتق مفاتيح قاعدة البيانات من MAC أو من بصمة الترخيص.
- لا سيرفر ولا API ولا اتصال مطلوب لإتمام البيع.

## تشغيل معاينة الواجهة

يتطلب Node.js 20.19+ وnpm. من هذا المجلد:

```powershell
cd apps/pos-desktop
npm install
npm run dev
```

المعاينة في المتصفح تستخدم بيانات تجريبية فقط؛ لا تحفظ مبيعات حقيقية ولا تستخدم قاعدة SQLCipher. بناء سطح المكتب يتطلب Rust stable وأدوات Microsoft C++/Windows SDK وWebView2 Runtime:

```powershell
npm run tauri dev
npm run tauri build
```

أداة التفعيل تُبنى من مشروعها المستقل:

```powershell
cd apps/activation-tool
npm install
npm run tauri build
```

لا يُبنى/يُوزّع `tools/license-issuer` ضمن مثبت POS أو مثبت ActivationTool. مفتاح التوقيع الحقيقي غير موجود في المستودع.

## تجربة سريعة بدون ترخيص

عند أول تشغيل على جهاز جديد يبدأ التطبيق **نسخة تجريبية محلية 7 أيام**
تلقائيًا، مسجَّلة في قاعدة البيانات المشفّرة ومربوطة ببصمة الجهاز.
بعد انتهائها يدخل التطبيق **مهلة سماح 14 يومًا**، ثم تتوقف وظيفة البيع حتى
صدور رخصة موقّعة. التفاصيل والخطط والأسعار في
[docs/LICENSING.md](docs/LICENSING.md).

## قبل تحويلها إلى نسخة متجر

1. حسم شمول ضريبة 14% وآلية التقريب، واعتمادها مع محاسب المتجر.
2. اعتماد سياسة المرتجعات ومهلة الإرجاع وحالات القطعة ووسائل رد المبلغ.
3. إعطاء موديلات قارئ الباركود، طابعة الفاتورة (58/80mm)، وطابعة الملصقات؛ اختبارها على Windows الفعلي.
4. اعتماد سياسة التجربة المتكررة، مهلة السماح وما يُسمح به بعد انتهاء الاشتراك، التسعير والتحصيل، وإجراءات النقل/إعادة التفعيل. المدد الحالية في مصدر الأداة: تجربة 7 أيام واشتراك 12 شهرًا تقويميًا.
5. تحديد ملفات النظام القديم وعينة CSV/XLSX منزوعة البيانات الحساسة لتصميم معاينة الاستيراد.
6. إنشاء مفاتيح إصدار الرخص داخل جهاز توقيع داخلي أو HSM، وتوقيع EXE ومثبت Windows بشهادة Code Signing.
7. إجراء اختبار قبول على نسخة Windows نظيفة، وانقطاع كهرباء واختبار استعادة من USB قبل ترحيل بيانات فعلية.
