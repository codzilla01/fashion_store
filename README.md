# نظام نقاط بيع وإدارة مخزون لمحل ملابس — POS

**المستهدف:** محل واحد حاليًا، مع `branch_id` في البيانات منذ البداية؛ Windows 10/11؛ واجهة عربية/إنجليزية؛ تشغيل محلي دون اتصال.

> **حالة المصدر في 2026-11-16:** يحتوي المستودع على مصدر تطبيق POS محلي بـ Tauri/React/Rust، ومشروع ActivationTool مستقل لطلب/استيراد الرخصة دون اتصال، ولوحة Super Admin مستقلة للمطور لإدارة الاشتراكات وتفعيل نسخ العملاء، وأداة إصدار/إدارة اشتراكات سطر أوامر تشارك نفس السجل.
>
> **ما تم قياسه على Windows حقيقي:** SQLCipher مفعّل (والفتح بمفتاح خاطئ يفشل)، ومفتاح قاعدة البيانات محمي بـDPAPI، والحقول الشخصية مشفّرة، والنسخ `.bkz` المشفّر يُنشأ ويُستعاد (وكلمة المرور الخاطئة مرفوضة)، والمهاجرات قابلة لإعادة الفتح. كل ذلك داخل `cargo test --test windows_security` على `windows-latest`.
>
> **ما أُضيف حديثًا:** **لوحة تحكم المالك** (تُفتح بالضغط المطول على الشعار) مع دخول ببصمة الجهاز (Windows Hello أو بصمة الجوال عبر WebAuthn) أو بكلمة مرور المالك، **سياسة مرتجعات مرنة** يتحكم فيها المالك من اللوحة وتُطبَّق فورًا في مكتب المرتجعات، **الضريبة اختيارية** (مطفأة افتراضيًا، وعند تشغيلها 14% غير شاملة للأسعار)، **الوضع النهاري والليلي**، ولوحة Super Admin بمفتاح توقيع في خزنة مربوطة بـWindows DPAPI.
>
> **ما أُضيف سابقًا:** تجربة محلية تلقائية 7 أيام مربوطة ببصمة الجهاز (مسجَّلة في `local_trial_state` بسجل append-only)، مهلة سماح 14 يومًا بعد انتهاء الترخيص، **طباعة الفواتير** (نص 58/80mm + HTML + إرسال مباشر إلى طابعة Windows عبر `winspool`)، حارس يمنع شحن بناء بلا مفتاح ترخيص إنتاجي، ودليل تسليم/تشغيل/ترخيص تجاري.
>
> **ما زال ناقصًا (بوابات حقيقية لا يمكن تجاوزها):** لا يوجد مفتاح توقيع إنتاجي،
> ولا مثبت موقّع بـCode Signing، ولا اختبار على طابعة/ماسح فعليين.
> الاستيراد والولاء والضريبة الاختيارية ورد الرصيد صارت منفّذة ومغطاة باختبارات.
> **لا تُدخل بيانات متجر حقيقية قبل اجتياز `docs/RELEASE-CHECKLIST.md`.**

## ما تم تثبيته من إجاباتك

- المقاسات: جداول دولية (مثل XS–XXL)، مع قابلية إنشاء مقاسات أخرى لكل فئة.
- الأجهزة: إعداد متعدد متوقع، يشمل ماسح باركود وطابعة فواتير وطابعة ملصقات؛ الموديلات وعرض الفاتورة لم تُحدّد.
- سياسة المرتجعات: مرنة، والمالك هو من يضبطها من لوحة التحكم الخاصة به (مدة الاسترجاع، قبول الأصناف المخفّضة، الحالات المسموح بإرجاعها للمخزون)، والقيمة الافتراضية 14 يومًا مضبوطة في قاعدة البيانات حتى يعمل مكتب المرتجعات من اليوم الأول.
- العملة والضريبة: EGP، والضريبة **اختيارية ومطفأة افتراضيًا**؛ وعند تشغيلها من لوحة المالك تكون 14% والأسعار المعروضة **غير شاملة** لها (تُضاف عند الدفع). لا يوجد أي إجبار على ضبط الضريبة قبل البيع، ويظل المالك قادرًا على تغيير النسبة أو طريقة العرض أو إيقافها في أي وقت.
- الباركود: استيراد الموجود وتوليد Code 128 داخليًا للمتغيرات التي لا تحمل باركود.
- الترخيص: تفعيل أوفلاين بملفي `.req` و`.lic`؛ أداة الإصدار تدعم تجربة موقعة 7 أيام واشتراكًا لمدة 12 شهرًا تقويميًا. مهلة السماح، سياسة تكرار التجربة، التسعير والتحصيل لم تُحسم.

## التقنية المقترحة

- Tauri 2.x + React/TypeScript وWebView2 على Windows.
- Rust backend؛ لا يُسمح للواجهة بإرسال SQL عام.
- SQLCipher مضمّن في بناء Windows، وقاعدة `rusqlite` لا تُفتح إلا بعد تطبيق المفتاح. طبقة الوصول تكون مستودعات typed/repository ومهاجرات SQL، بدل إضافة ORM لا يضمن SQLCipher فعليًا.
- تخزين المفتاح المحلي عبر Windows DPAPI، مع سر عشوائي مستقل عن بصمة الجهاز. لا تُشتق مفاتيح قاعدة البيانات من MAC أو من بصمة الترخيص.
- خزنة مفتاح التوقيع في لوحة Super Admin مربوطة بـWindows DPAPI في حساب المشغّل، فنسخ ملف الخزنة إلى جهاز أو حساب آخر لا يفتحها.
- لا سيرفر ولا API ولا اتصال مطلوب لإتمام البيع.

## تشغيل معاينة الواجهة

يتطلب Node.js 20.19+ وnpm. من هذا المجلد:

```powershell
cd apps/pos-desktop
npm install
npm run dev
```

المعاينة في المتصفح تستخدم بيانات تجريبية فقط؛ لا تحفظ مبيعات حقيقية ولا تستخدم قاعدة SQLCipher. بناء سطح المكتب يتطلب Rust stable وأدوات Microsoft C++/Windows SDK وWebView2 Runtime:

```powershell
npm run tauri dev
npm run tauri build
```

أداة التفعيل ولوحة المطور تُبنيان من مشروعيهما المستقلين:

```powershell
cd apps/activation-tool
npm install
npm run tauri build

cd ../super-admin
npm install
npm run tauri build
```

لا يُبنى/يُوزّع `tools/license-issuer` ولا `apps/super-admin` ضمن مثبت POS أو مثبت ActivationTool. مفتاح التوقيع الحقيقي غير موجود في المستودع:-living في خزنة اللوحة على جهاز المطور فقط.

## تجربة سريعة بدون ترخيص

عند أول تشغيل على جهاز جديد يبدأ التطبيق **نسخة تجريبية محلية 7 أيام**
تلقائيًا، مسجَّلة في قاعدة البيانات المشفّرة ومربوطة ببصمة الجهاز.
بعد انتهائها يدخل التطبيق **مهلة سماح 14 يومًا**، ثم تتوقف وظيفة البيع حتى
صدور رخصة موقّعة. التفاصيل والخطط والأسعار في
[docs/LICENSING.md](docs/LICENSING.md).

## تحويلها إلى نسخة متجر

أُضيف مسار إصدار مؤتمت في [.github/workflows/release.yml](.github/workflows/release.yml)
ويمنع نشر أي نسخة تجارية قبل تحقق كل البوابات. اتبع [دليل الإصدار](docs/RELEASE-RUNBOOK.md).

### تم اعتماده

- الضريبة **اختيارية**: مطفأة افتراضيًا، وعند تشغيلها 14% غير شاملة وتُقرَّب لأقرب ١ ج.م —
  [القرارات](docs/RELEASE-DECISIONS.md).
- المرتجعات 14 يومًا مع رد رصيد للعميل، والإرجاع للمخزون لحالتي `UNOPENED` و`NEW_TAGS`.
- خطة سنوية 12,000 ج.م، ونقل جهاز مجاني أول مرة ثم 500 ج.م.
- نسخ يومي على USB مع اختبار استعادة أسبوعي.

### ما زال مطلوبًا قبل أول بيع

1. إضافة `NASEEJ_LICENSE_PUBLIC_KEY_HEX` و`CODE_SIGNING_PFX_BASE64`
   و`CODE_SIGNING_PFX_PASSWORD` كأسرار في GitHub Actions. لا توضع القيم في Git.
2. تنفيذ واعتماد [سجل اختبار الأجهزة](docs/ACCEPTANCE-RECORD.md) على Windows
   مع الطابعة والماسح، وتغيير حالته إلى `ACCEPTANCE_STATUS: PASS`.
3. تشغيل **Production release** من GitHub Actions أو دفع وسم `v0.1.0`؛
   سينتج مثبتين موقّعين و`SHA256SUMS.txt` و`sbom.json` و`RIGHTS.txt`.
4. التحقق من التوقيع والبصمة على جهاز المتجر قبل إدخال بيانات فعلية.

> لا تُدخل بيانات متجر حقيقية قبل اجتياز [قائمة بوابات التسليم](docs/RELEASE-CHECKLIST.md)
> وتوقيع سجل القبول. تبقّى اختبار الطابعة والماسح والاستعادة على جهاز فعلي؛
> راجع [حالة الاختبار](docs/TESTING.md).
